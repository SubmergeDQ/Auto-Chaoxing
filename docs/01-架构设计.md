# 01 · 架构设计

## 1. 设计目标

| 目标 | 约束 |
|---|---|
| 双端同源 | Android 与 Windows 共用 90% 以上代码，平台差异收敛到一个接口 |
| 协议可替换 | 学习通改版时只改 `core/` 的解析层，不动 UI |
| 可中断可恢复 | 手机被系统杀、电脑关机，重启后从断点继续 |
| 可解释 | 每个任务点为什么成功/失败都能在日志里找到原始请求与响应摘要 |
| 不越权 | 不申请无障碍、不 root、不注入系统进程，只做 HTTPS + 可选 WebView |

## 2. 分层

```
┌──────────────────────────── UI 层（Flutter Widgets）────────────────────────────┐
│ 课程页    任务页（队列+进度）   日志页    设置/账号页    考试提醒                  │
└───────────────────────────────────┬─────────────────────────────────────────────┘
                                    │ Riverpod Provider（状态即真相）
┌───────────────────────────────────▼─────────────────────────────────────────────┐
│ 编排层  TaskRunner                                                              │
│  · 串行队列（一个账号同时只跑一个任务，避免并发风控）                            │
│  · 节流器（每题 2–4s 随机、每段进度 1s、每课程间隔 30s 起）                      │
│  · 断点续跑（checkpoint 落盘：课程 → 章节 → 任务点 → 已上报时间点）              │
│  · 收尾校验（平台回执为准，不信任本地"已完成"）                                  │
└───────────────────────────────────┬─────────────────────────────────────────────┘
                                    │
┌───────────────────────────────────▼─────────────────────────────────────────────┐
│ 能力层                                                                          │
│  ChaoxingApi(dio+cookie_jar)  Crypto(md5/aes)  Parser(HTML→mArg)                │
│  AnswerProvider(题库/LLM)     WebViewBridge(Android 作业提交)                    │
└───────────────────────────────────┬─────────────────────────────────────────────┘
                                    │
┌───────────────────────────────────▼─────────────────────────────────────────────┐
│ 平台层  PlatformServices（抽象）                                                │
│  Android: 前台服务 + 常驻通知 + inappwebview + secure_storage                    │
│  Windows: 无后台限制（Isolate 即可） + WebView2（可选） + DPAPI + 托盘           │
└─────────────────────────────────────────────────────────────────────────────────┘
```

## 3. 模块职责

| 模块 | 位置 | 职责 | 不允许做的事 |
|---|---|---|---|
| `crypto.dart` | core | AES-CBC 登录加密、MD5 进度签名 | 不持有网络与状态 |
| `chaoxing_api.dart` | core | 所有 HTTP 请求、Cookie 维护、错误归一 | 不含业务循环与重试策略 |
| `models.dart` | core | 课程/章节/任务点/题目/结果 | 不做 IO |
| `task_runner.dart` | core | 编排、节流、断点、幂等 | 不直接拼 URL |
| `answer_provider.dart` | core | 题目 → 答案（题库 API / LLM） | 不决定交不交卷 |
| `platform_services.dart` | platform | 后台/通知/WebView/存储 | 不含业务逻辑 |

## 4. 关键数据流：刷视频

```
用户点「开始本章」
   → TaskRunner.checkpoint 写 {courseId, chapterId, index:0}
   → ChaoxingApi.cards(courseId, classId, chapterId)
        → 正则取 mArg JSON → defaults(reportUrl/fid) + attachments[]
   → 过滤 type==video 且 job==true
   → 对每个任务点：
        ChaoxingApi.videoStatus(objectId)        // dtoken + duration
        for playTime in 0, 60, 120 … duration:
            enc = Crypto.progressEnc(...)
            ChaoxingApi.reportProgress(...)      // 命中 isPassed 立即退出
            checkpoint(index=已上报秒数)
   → 全部结束 → 写结果（成功/失败/需要人工）→ 通知
```

## 5. 任务状态机

```
idle → preparing → running → (succeeded | failed | needs_attention | stopped)
                     │
                     ├─ 网络错误 → retry(≤3, 指数退避) → 仍失败 → failed
                     ├─ 平台返回"需要人脸/验证码" → needs_attention（不重试轰炸）
                     ├─ 用户停止 → stopped（保留 checkpoint）
                     └─ 应用被杀 → 重启后从 checkpoint 进入 running
```

`needs_attention` 是刻意的一等状态：**平台要求人工时，程序必须停下来等人**，而不是换参数硬撞。
这是被风控清空进度最常见的原因。

## 6. 存储模型

| 表/文件 | 内容 | 生命周期 |
|---|---|---|
| `account` | 昵称、uid、fid、学校、加密后的 cookie | 长期，keystore/DPAPI 加密 |
| `course` | courseId/classId/cpi/名称/教师 | 每次同步覆盖 |
| `task_checkpoint` | 课程-章节-任务点-已上报位置 | 任务结束清理 |
| `task_log` | 时间戳、级别、请求摘要、响应摘要 | 保留最近 5000 条，可导出 |
| `answer_cache` | 题干 hash → 答案 | 可选，避免重复扣题库次数 |

## 7. 错误处理约定

- 所有 API 返回 `Result<T>`（`Ok` / `Err(code, message, raw)`），**禁止用异常穿透到 UI**。
- 401/登录失效统一映射为 `AuthExpired`，由上层触发重新登录，不自动重试。
- 平台返回 HTML 而非 JSON 时，先判「登录页 / 活动未开始 / 需要验证」三类特征串，再抛解析错误。
- 每个请求记录 `method + path + 状态 + 耗时`，不记录 cookie 与密码。

## 8. 可观测性

- 日志分四级：`trace`（完整请求）、`info`（任务进度）、`warn`（可重试失败）、`error`（需要人）。
- 任务页固定显示：当前任务点、总进度、最近 3 行日志、失败清单。
- 导出诊断包：脱敏后的 cookie 存在性、协议版本探测结果、最近 500 条日志。

## 9. 与旧方案的边界

本仓库**不复用**教务助手 / 九九助手的代码，只参考其公开可见的协议参数与页面结构；
宿主插件（`community.chaoxing`）与本项目是互不依赖的两条实现路径。
