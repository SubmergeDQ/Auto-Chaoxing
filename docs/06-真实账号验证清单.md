# 06 · 真实账号验证清单

这份清单解决一个具体问题：**代码里还有几处「按协议推断、没用真实账号核对」的地方**。
它们不影响编译和单测，但只有真账号跑一遍才能确认。照着做一遍，大约 20 分钟，
就能把「推断」变成「已验证」或者「确实不对，需要改」。

> 只用自己的账号、自己已选修的课程。看到人脸抽检、验证码、二次验证**立刻停**，直接关掉本次执行，
> 不要试图绕过——这几个是平台的风控入口，硬闯的代价通常是进度清零甚至限制登录。

---

## 0. 准备

1. 用浏览器正常登录一次学习通，确认账号没有被要求二次验证。
2. 在课程里挑**一章只有 1–2 个短视频**的章节，最好是「已经看过一部分」的（这样能验续跑）。
3. 起应用：

```bash
export PATH="/d/dev/flutter/bin:/d/dev/flutter/bin/cache/dart-sdk/bin:$PATH"
flutter pub get
flutter run -d windows      # 或 flutter run -d android
```

4. 准备好记录：每验证一项，把 `任务执行` 页的**复制日志**粘到一个文本文件里，按下面的编号存。

## 1. 只读链路（应全部通过）

| 1.5 | 设置页重新连接 | 就地恢复，不用重登 | — |

## 2. 执行一章（核心）

| # | 操作 | 期望 | 记录 |
|---|---|---|---|
| 2.1 | 展开章节，点「执行本章视频」 | 弹确认框，写明任务点数量、耗时量级、不在本次范围的内容 | 截图 `confirm` |
| 2.2 | 点「开始执行」 | 切到任务执行页，状态「运行中」，进度行出现 `已通过 0 / N · 正在上报 xxx` | 截图 `running` |
| 2.3 | 等第一个任务点跑完 | 日志出现 `通过：xxx`，进度条前进，平台网页端该任务点变绿 | 复制日志 |
| 2.4 | 中途点「停止执行」 | 状态变「已停止」，**不计为失败**，日志写 `已停止：xxx（下次可从当前进度继续）` | 复制日志 |
| 2.5 | 点「再次执行」 | 重新开始；已通过的任务点**不应再从 0 重刷**（见第 3 节） | 复制日志 |

**判定**：2.3 的「平台网页端变绿」是唯一的成功标准。应用里写「已通过」只代表本地收到了
`isPassed: true`，两者不一致时以后台为准。

## 3. 断点续跑字段证伪（这轮的重点）

代码依赖卡片里的两个字段，**它们的语义没有用真实账号核对过**：

| 字段 | 当前用法 | 要确认什么 |
|---|---|---|
| `isPassed` | 明确为 `true` 时整段跳过任务点 | 这个键名到底存不存在？存在时是否只在通过后为真？ |
| `attDuration` | 作为续跑起点（秒） | 它是「累计观看时长」还是「本次会话时长」？单位是不是秒？ |

**操作**：对**同一章**连续执行两次（第一次跑到一半就停），看第二次的日志。

三种结果对应三种结论：

| 日志里看到 | 说明 | 下一步 |
|---|---|---|
| `跳过：xxx（平台已标记通过）` | `isPassed` 存在且解析正确 | 在 `docs/03` 3.3 的表格里把「待实测」改成「已验证」 |
| `从 3:20 继续：xxx（卡片累计时长）` 且起点接近网页端显示的进度 | `attDuration` 是累计时长 | 同上；顺带确认续跑后平台进度没有回退或清零 |
| 两个都没有，全是 `开始：xxx` | 卡片没给这两个字段，或键名不对 | 停下来：需要抓一份 `knowledge/cards` 的原始响应，从 `mArg` 里找真实的键名，再改 `_readPassed` |

> 第三种情况**不是功能坏了**：代码在字段缺失时会退回「从 0 开始逐点上报」，也就是 0.3.0 的行为。
> 它只是没吃到优化，不会做错事。

## 4. 异常处置（能触发几条就验几条）

| # | 怎么触发 | 期望行为 |
|---|---|---|
| 4.1 | 执行中去另一台设备退出登录 | 状态立刻变「需要人工」，原因写「登录已失效，请重新连接账号后再继续」，**不继续刷后面的任务点** |
| 4.2 | 找一章「上一章测验未提交」的 | 状态「需要人工」+「章节未开放：上一章未完成或测验未提交」，不发起任何上报 |
| 4.3 | 平台弹人脸抽检 / 验证码 | 状态「需要人工」，原因照抄平台文案；应用**不会**自动重试 |
| 4.4 | 执行中切到后台 5 分钟再回来 | 记录实际发生了什么：继续跑 / 停住 / 被系统挂起。当前**没有**后台保活，停住属预期 |
| 4.5 | 断网 10 秒再接回 | 单次失败会重试（最多连续 3 次），恢复后应继续；连续失败则记 `失败：xxx -> …` 并继续下一个任务点 |

## 5. 记录什么

每次验证存一份，**复制日志已经做过脱敏**（手机号、令牌、签名被抹掉），可以直接贴出来：

```
验证项：#3 断点续跑
结果：看到「从 2:40 继续：1.2 数列的极限（卡片累计时长）」
网页端进度：2:41 / 10:00
判断：attDuration 为累计时长，续跑生效
备注：第二次执行没有重复上报前 2:40
```

需要附截图的三处：确认框、运行中、需要人工（或失败）。

- **文档 / 阅读、测验**：还没接线，不在这份清单范围。

  验证时重点看 `activelist` 的时间字段格式、`preSign` 判定页与提交回执的原文。
- **作业**：0.3.7 已接入列表与网页作答入口；`task-list` 的字段名、已交标记与截止时间格式待验证。
  代提交与自动答题未做，不在这份清单范围。
- **多账号**：0.3.9 已接线；真机验证时重点看两点——两个账号来回切换后课程/执行状态不串，
  以及旧版单会话升级后无需重新登录。
