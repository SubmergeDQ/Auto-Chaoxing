# 03 · 协议与接口

> 标注说明：**已验证**= 在本仓库样本里找到完整实现且参数自洽；**待实测**= 结构清楚但缺一次真实抓包确认。
> 所有请求默认带登录 cookie；`Referer` 不是可选项，学习通多处按 Referer 判来源。

## 0. 通用约定

| 项 | 值 |
|---|---|
| UA | 移动端 Chrome UA 或与官方 App 一致的自定义 UA |
| 编码 | 表单 `application/x-www-form-urlencoded`，响应多为 JSON 或 HTML |
| 时间戳 | 毫秒，参数名常见 `_t` / `_dc` |
| 随机串 | 32 位小写字母数字，用于 `enc` / `openc` 之类占位参数 |
| 登录态 | cookie：`_uid`、`_d`、`fid`、`uf`、`vc3` 等；失效表现为返回登录页 HTML |

### 错误特征串（解析前先判）

| 特征 | 含义 | 处置 |
|---|---|---|
| `passport2.chaoxing.com/login` / `id="loginForm"` | 登录失效 | 触发重新登录 |
| `校验失败，未查询到活动数据` | 活动会话失效 | 重新拉活动列表 |
| `下次早点哦` / `签到已截止` | 签到已结束 | 标记结束，不重试 |
| `需要人脸` / `openCheckFaceFlag=1` | 人脸抽检 | `needs_attention` |
| `id="captcha"` / `needCaptcha=1` | 需要验证码 | 转 WebView 人工 |

## 1. 登录 · 已验证

```
POST https://passport2.chaoxing.com/fanyalogin
Content-Type: application/x-www-form-urlencoded

fid=-1
refer=https://i.chaoxing.com
t=true
forbidotherlogin=0
validate=
uname=<AES-128-CBC(uname)>
password=<AES-128-CBC(password)>
```

- 算法：AES/CBC/PKCS7，key = iv = `u2oh6Vu^HWe4_AES`（base64 `dTJvaDZWdV5IV2U0X0FFUw==`），输出 base64。
- 注意首字母是 `u` 不是 `m`：`bTJv...` 与 `dTJv...` 只差一个字节，密钥错时服务端不会报「解密失败」，而是回 `{"msg2":"用户名或密码错误","status":false}`，极易误判成密码错。2026-11-12 就是踩在这里。
- 成功：`{"status": true, ...}`
- 需要人工：`containTwoFactorLogin` / `needVcode` / `weakpwd` / `passwordTimeout` 任一为真 → 打开内嵌浏览器。
- 失败：`msg2` / `mes` / `msg` 里是中文原因，直接展示。

## 2. 课程列表 · 已验证

```
GET https://mooc1-api.chaoxing.com/mycourse/backclazzdata?view=json&rss=1
```

解析：

```
channelList[].content.course.data[0].id        → courseId
channelList[].content.id                       → classId
channelList[].content.cpi                      → cpi
channelList[].content.course.data[0].name      → 课程名
channelList[].content.course.data[0].teacherfactor → 教师
channelList[].content.isFiled / isretire       → 已归档/已结课
```

`courseId:classId` 作为课程主键（同一门课可有多个 classId）。

## 3. 章节与任务点 · 已验证

### 3.1 章节列表

```
GET https://mooc1.chaoxing.com/mycourse/studentcourse
    ?courseId=…&clazzid=…&forcedJoin=1&knowledgeid=0&ut=s&cpi=…
Referer: https://i.chaoxing.com
```

HTML 里用 `chapterId=(\d+)` 提取，标题在锚点后文本；`mooc2=1` 时是折叠结构，取全部即可。

### 3.2 章节卡片（**最关键**）

```
GET https://mooc1.chaoxing.com/knowledge/cards
    ?clazzid={classId}&courseid={courseId}&knowledgeid={chapterId}
    &num={page}&ut=s&cpi={cpi}&v=20160407-1
Referer: https://mooc1.chaoxing.com/mycourse/studentstudy
         ?chapterId=…&courseId=…&clazzid=…&cpi=…&enc={随机32}&mooc2=1&openc={随机32}
```

响应 HTML 内含 `mArg = {...};`（外层包在 `try{…}catch(e){}` 里），正则：

```
mArg\s*=\s*(\{.+?\});\s*\}\s*catch
```

JSON 结构：

```
defaults.reportUrl      // 进度上报基址（后续所有 video/document 都打这里）
defaults.fid            // 机构 id，缺失时用 666
defaults.userid         // 用户 uid
attachments[]           // 任务点数组
  job == true           // 是任务点（false 的是非任务点内容）
  type                  // video / document / workid / read / live …
  jobid                 // 任务点 id
  otherInfo             // 上报必带的加密串
  property.objectid     // 资源 id（视频用于取 dtoken）
  property.name         // 标题
  property.doublespeed  // 1 = 允许倍速
  property.fastforward  // "false" = 允许倍速
  property.rt           // 播放倍率（默认 "0.9"）
  attDuration / attDurationEnc / videoFaceCaptureEnc   // 反作弊字段，原样回传
  property.isPassed / isPassed   // 候选字段：该任务点是否已通过（待实测，见 3.3）
```

> 任务点未开放、上一章未完成、章节测试未提交时，`mArg` 可能不出现 —— 属于预期，不要当解析错误。

### 3.3 断点续跑的依据（**已实现，字段语义待实测**）

判断「哪些任务点不用再跑」只有卡片这一个来源，`ananas/status` 不返回已看时长：

| 依据 | 字段 | 当前用法 | 风险 |
|---|---|---|---|
| 已通过 | `attachments[].isPassed` / `property.isPassed` | **只在明确 `true` 时整段跳过**；字段缺失按「不知道」处理，照常执行 | 字段名未用真实账号核对；若平台改用别的键名，效果是「不跳过」，不会误跳 |
| 已看进度 | `attachments[].attDuration`（秒） | 续跑起点 = 该值（夹紧到 `[0, duration]`），首跳 `isdrag=3`，到结尾那次仍 `isdrag=4` | `attDuration` 究竟是「累计时长」还是「本次会话时长」未核实；若是后者，起点会偏小——只是多做几次无害上报，不会跳步 |

判定口径：**宁可多跑，不可误跳。** 两个字段都缺失时行为与 0.3.0 完全一致（从 0 开始逐点上报），
因此这套逻辑是纯增益的。日志里会显式写出依据（`跳过：xxx（平台已标记通过）` /
`从 3:20 继续：xxx（卡片累计时长）`），首次用真实账号跑一章就能验证字段真假——
看到「跳过」或「从 x 继续」说明字段存在且被正确解析，全都显示「开始」说明卡片没给这些字段。

## 4. 视频进度 · 已验证（核心）

### 4.1 取元数据

```
GET https://mooc1.chaoxing.com/ananas/status/{objectid}?k={fid}&flag=normal&_dc={ms}
Referer: https://mooc1.chaoxing.com/ananas/modules/video/index.html?v={videoV}
→ {"status":"success","objectid":"…","duration":1234,"dtoken":"…"}
```

`duration` 单位秒；`dtoken` 是上报路径的第一段。

### 4.2 进度上报

```
GET {reportUrl}/{dtoken}?clazzId=…&playingTime=…&duration=…&clipTime=0_{duration}
    &objectId=…&otherInfo=…&jobid=…&userid=…&isdrag={3|4}&view=pc
    &enc={md5}&rt={rt}&videoFaceCaptureEnc={…}&dtype=Video&_t={ms}
    &attDuration={…}&attDurationEnc={…}
```

签名：

```
enc = md5( "[{classId}][{uid}][{jobid}][{objectid}][{playTime*1000}]"
           + "[d_yHJ!$pdA~5][{duration*1000}][0_{duration}]" )
```

- `playTime` 以秒计，步长 60（或 60×倍速）；最后一跳 `playTime = duration`、`isdrag = 4`。
- 命中 `{"isPassed": true}` 即该任务点完成。
- 连续失败 3 次放弃并记录；`isdrag=4` 但未通过 → 「已看完但未判定完成」，多为人脸抽检或倍速限制。
- 已知风险：倍速 > 2、同账号多端、夜间长时间挂机 → 平台可能清空进度。

### 4.3 文档 / 阅读任务点

结构同卡片，`type=document`，上报走 `reportUrl` 的 document 分支，参数与 video 类似但无 `dtoken` 语义。
**待实测**：需要一次真实文档任务点的请求样本才能定字段表。

## 5. 章节测验 / 作业 · 部分已验证

### 5.1 列表

```
GET https://mooc1-api.chaoxing.com/work/task-list?courseId=…&classId=…&…
```

返回作业条目：`id/workId`、`name`、`status`、`startTime/endTime`、是否已交。
考试列表是 `https://mooc1-api.chaoxing.com/exam/phone/task-list`（仅用于提醒）。

### 5.2 作答页

```
GET https://mooc1.chaoxing.com/mooc-ans/work/doHomeWorkNew
    ?courseId=…&classId=…&workId=…&…
```

要点：

- 题目结构：题干、题型（0 单选 / 1 多选 / 2 填空 / 3 判断）、选项真实值在 `em[id-param]`、
  填空题是 `input.answerInput`（新版）或 `ueditor` iframe 里的 `<p>`（旧版）。
- 页面里有一批隐藏字段（`workAnswerId`、`temAnswer`、`totalQuestionNum`、`fullScore` 等），
  **提交时必须原样带回去**。

### 5.3 提交 · 待实测

页面自己的入口是 `submitData()` / `noSubmit()`（保存）。纯 HTTP 复刻需要一次抓包确认字段集合；
未确认前，Android 端走「隐藏 WebView 打开作答页 → 注入答案 → 点页面按钮」的保真路线。

**无论哪条路线，提交后都要回读 `task-list` 校验 `completed`**，否则会出现「本地以为交了、
平台没收到」的重复提交。

### 5.4 题库

```
POST https://tk.wanjuantiku.com/api/query?token={token}&version={v}
Content-Type: application/x-www-form-urlencoded

tm=<题干>&type={0-3}&wid={workId}&answernum={填空数}&cid={courseId}
&options=[…选项文本…]&ai={0|1}&coursename=<课程名>
→ {"code":1,"data":"答案","left":剩余次数,"msg":"…"}
```

- 查一次扣一次；`left` 归零后必须停止自动答题。
- 备选：自有 LLM（客观题尚可，主观题/编程题不可靠）。
- 第三方题库域名、额度、协议随时可能变，**必须做可插拔的 `AnswerProvider`**。

## 6. 签到 · 已验证

### 6.1 活动列表

```
GET https://mobilelearn.chaoxing.com/v2/apis/active/student/activelist
    ?fid=0&showNotStartedActive=0&courseId=…&classId=…&cpi=…
→ data.activeList[]：id、nameOne、type(2 签到/74 签退)、status、startTime、endTime、otherId、ext
```

`ext` 是会话数据，**短时效**，随活动详情返回，必须现场取用。

### 6.2 预签到

```
POST https://mobilelearn.chaoxing.com/newsign/preSign
     ?courseId=…&classId=…&activePrimaryId={id}&general=1&sys=1&ls=1&appType=15
     &uid={puid}&isTeacherViewOpen=0
form: ext={活动 ext}
```

返回 HTML，判定：已签到 / 需要人脸 / 验证码 / 已结束 / 可签到。

### 6.3 提交签到

```
GET|POST https://mobilelearn.chaoxing.com/pptSign/stuSignajax
    ?courseId=…&classId=…&activeId=…&uid=…&name=…&fid=…
    &clientip=&useragent=&appType=15&latitude=-1&longitude=-1
    &enc=&enc2=&validate=&signCode=&objectId=&type=

（有坐标时追加）
location       = {"result":1,"latitude":..,"longitude":..,"address":".."}
locationResult = 同上 + {"mockData":"{\"strategy\":0,\"probability\":-1}"}
```

- 回执：`success` / `success2`（已结束）/ `已经签到` / `validate`（要验证码）/ `error`。
- 人脸签到：先 `GET /pptSign/check-face-result?activeId=…&faceResult={…}` 取 `enc`，
  再带 `currentFaceId / faceEnc / ifCFP=0` 提交；照片需先上传到 `pan-yz.chaoxing.com` 拿 `objectId`。
- 定位是**协议字段**，不需要伪造系统 GPS，也不需要 hook。
- 幂等：同一 `activeId` 已成功则永不再发。

### 6.4 拼图验证码

`captchaId = Qt9FIw9o4pwRjOyqM6yizZBh682qN2TU`；
`iv = md5(captchaId + "slide" + nonce)`，`token = md5(time + captchaId + "slide" + key) + ":" + (time+300000)`。
滑块距离需要图像识别（OpenCV/ONNX），**第一版不做**，直接转人工。

## 7. 速率与节流（经验值）

| 场景 | 间隔 |
|---|---|
| 视频进度上报 | 1s / 段 |
| 题目作答 | 2–4s 随机 |
| 作业之间 | 30s 起 |
| 签到轮询 | 60s，仅在有课的时间段 |
| 登录失败后 | 不自动重试，等人工 |

并发：**单账号严格串行**。多课程并发是被判定异常的常见原因。
